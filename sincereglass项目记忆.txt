BlogArticle interface — registry entry schema
Required fields:

slug: string
title: string
excerpt: string ← NOT description
targetKeyword: string
searchKeywords: string[] (≥10 per SOP v2.2 C20)
publishDate: string (YYYY-MM-DD)
category: BlogCategory — literal union: 'Technical Guide' | 'Industry News' | 'Product Knowledge' | 'Project Case Study' | 'Buyer Guide' | 'Manufacturing'
tags: string[]
heroImage: string
heroImageAlt: string ← REQUIRED, not optional
author: { name, url, title?, bio?, image? } — object, NOT string. Use exported DEFAULT_AUTHOR constant.
cluster: BlogCluster — literal union: 'comparison' | 'technical' | 'application' | 'buyer-guide' | 'product'
readingTime: number
Optional:

secondaryKeywords?: string[]
updatedDate?: string
heroImagePrompt?: string
reviewedBy?: { name: string; title?: string } — object, not string
tldr?: string[]
buyerFaq?: Array<{q,a}>
relatedProductSlugs?: string[]
articleType?: 'comparison' | 'technical' | 'buyer-guide' | 'case-study' — DIFFERENT from category; limited to these 4 lowercase values
translations?: Partial<Record<'es'|'de'|'ar'|'fr'|'ru', string>>
changelog?: Array<{date, note}>
featured?: boolean
isPillar?: boolean

Canonical page.tsx skeleton for new blog articles
tsx
import type { Metadata } from "next";
import BlogArticleLayout, {
  generateArticleMetadata,
  articleJsonLd,
  type TOCItem,
} from "@/components/blog/BlogArticleLayout";
import TLDRBox from "@/components/blog/TLDRBox";
import FAQ from "@/components/blog/blocks/FAQ";
import { blogArticles } from "@/lib/blog-registry";
import { makeAlternates } from "@/lib/i18n";

const SLUG = "your-slug";
const article = blogArticles.find((a) => a.slug === SLUG)!;

export const metadata: Metadata = {
  ...generateArticleMetadata(article),
  alternates: makeAlternates(`/blog/${SLUG}`),
};

const toc: TOCItem[] = [
  { id: "h2-id", text: "H2 Text", level: 2 },
];

const faqItems = [{ q: "...", a: "..." }];

export default function Page() {
  const schemas = articleJsonLd(article, faqItems);
  return (
    <>
      {schemas.map((s, i) => (
        <script key={i} type="application/ld+json" dangerouslySetInnerHTML={{__html: JSON.stringify(s)}} />
      ))}
      <BlogArticleLayout article={article} toc={toc}>
        {/* body */}
      </BlogArticleLayout>
    </>
  );
}
Common wrong assumptions (previous failures catalog)
2026-10-29 full-session Props disaster on Article #23: named imports for all 8 components, wrong paths for TLDRBox + InlineQuoteCTA, BlogArticleLayout treated like a dumb wrapper (passed slug/title/faqItems), author/reviewedBy as strings, category field used articleType values, RelatedProductsCards used productSlugs, LeadMagnetCTA used headline/subtext. All avoidable by project_read before writing. Root cause: did not call project_info + project_read at the start of writing — relied on memory which was wrong on many details.
Workflow rule: BEFORE writing or editing any blog article page.tsx or registry entry, project_read BlogArticleLayout.tsx + blog-registry.ts + the specific components the article will use. Do NOT guess from memory; this cheatsheet is the fallback but project_read is the ground truth.
RelatedProductsCards image-path bug (fixed 2026-11-18, SG-RELATED-CARDS-FIX-V1)
PRODUCT_MAP in RelatedProductsCards.tsx used /images/products/*-card.jpg which never existed → every blog product card showed broken image. Correct paths = the files products.ts actually uses: tempered.jpg / laminated.jpg / insulated.jpg / enameled.jpg (low-e-glass reuses insulated.jpg). When adding product cards, point image at a file that exists in public/images/products/, not an invented -card variant.
Gotcha: an arrow written as → in JSX text (between tags) renders literally as "→" — JSX text does not process backslash escapes. Use the real → character or {"→"} as a JS expression. (Taglines worked because –/× sit inside JS string literals where escapes do apply.)
Deploy purge-comma bug — recurs, fix at source (2026-11-18, #31 then #32)
The purgeEntry function copied across article deploy scripts inserts its marker comment right after the secondaryKeywords closing ], which pushes the array's trailing comma onto the end of the // comment line (commenting it out) → build fails Expected ',', got 'searchKeywords'. Hit on #31 (fix-registry-purge-comma.mjs) and again on #32 (fix-article-32-purge-comma.mjs). Future deploy scripts: fix at source — place the marker comment BEFORE ], or emit ] + comma on the same line then the comment, so the array's terminating comma stays on the ] line.

Windows findstr 与 UTF-8（2026-10-27）
Windows cmd 的 findstr 用系统 ANSI 码页（简中环境是 GBK）解码文件；UTF-8 文件里的非 ASCII 字符（如 Rₘᵢₙ、中文、西语重音）会显示乱码并可能触发"写入错误"
验证文件实际内容必须用 PowerShell + -Encoding UTF8：powershell -command "Get-Content <file> -Encoding UTF8 | Select-Object -Index N"（Index 是 0-based，所以第35行是 Index 34）
项目所有 .ts/.tsx/.json 源文件都是无 BOM 的 UTF-8，Node 脚本写入时直接 writeFileSync utf8 不会破坏
Deploy脚本安全规则（2026-10-27事故教训）

增量 patch 比重写更安全（2026-10-27教训）
对已部署的高流量文章做改进，默认用 "anchor-based 增量插入 patch" 而不是整文件重写：风险小、幂等、可回滚
Patch 块必须加唯一标记（如 GROK-INSERT-V1:xxx）供下次脚本检测跳过，实现幂等

2026-10-30 事故 Phase B TestReportDownload.tsx 反复 SWC "Expected jsx identifier" 报错：根因是 Node writeFileSync 把 UTF-8 字节在中文 Windows PowerShell 环境里再次经 GBK 转码，—/×/· 等 Unicode 字符变成 鈥?/脳/路 乱码字节序列，SWC 解析失败后把前面的 Record<Bucket, ...> 泛型 < 当成 JSX 开始，连锁导致真正的 <section> 位置报错。规则：生成 Sincere Glass TSX 组件模板时，正文一律用 ASCII 字符（em dash 用 -、× 用 times、· 用 and、& 用 and），把 Unicode 排版符号留给运行时的 CSS/JS 生成（如需）或用 HTML entities。PowerShell writeFileSync 的 .tsx.txt 模板必须用 [System.IO.File]::WriteAllText(path, content, (New-Object System.Text.UTF8Encoding $false)) 以无 BOM UTF-8 写入，避免 BOM 或 GBK 混用。
Sincere Glass 项目 TSX 组件避免在 as unknown as 后直接跟泛型 Record<Bucket, Report[]>，Next.js 14 SWC 在类型断言+JSX 返回场景下有时会把泛型 < 当成 JSX 开始；改用 const x = data as any; const y = x[key] as Report[] 两步走。
Sincere Glass 项目 tsconfig strict 开启，TSX 组件 props 必须显式类型声明（即使只用一个 prop，也写 props: { bucket: string }），对象字面量以 string 索引时需 (obj as any)[key] 跳过索引签名检查。
